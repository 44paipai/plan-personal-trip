# 个人旅行策划

如果用户提供了个人偏好，先把它们整理成默认偏好而非不可覆盖的硬规则；本次用户说明永远优先。没有提供个人偏好时，不要替用户虚构长期偏好。

## 选择工作模式

- 目的地或时长未定：先研究并建立候选池，再给建议时长与路线，不要先反问用户“想玩什么”。
- 目的地已定：围绕可玩内容、移动成本、季节和体力负担设计路线。
- 用户要 Excel：完成路线决策后，再读 [references/excel-deliverable.md](references/excel-deliverable.md)，并使用 `spreadsheets:Spreadsheets` 生成、渲染和验证工作簿。
- 用户只要偏好分析或问题清单：输出策划逻辑、已知偏好、仍需确认项，不擅自制作完整行程。

## 核心流程

### 1. 整理“已知、未知、约束”

提取出发地、人数与特殊人群、可用天数、时间弹性、预算状态、体力、节奏、住宿取向、必须体验和明确排除项。用户说“不知道”时，把它当作需要研究后给选项的信号，不重复追问。

只有会实质改变路线的问题才需要询问。优先级通常是：特殊人群或硬性体力限制 → 出发地与天数 → 日期弹性 → 预算边界 → 兴趣取舍。若日期、预算或景点均未知，先用目的地信息给出季节、消费和玩法档位，再让用户选择。

### 2. 研究目的地并建立候选池

对会随时间变化的交通、开放时间、票价、预约、施工、天气与政策进行联网核实，优先官方或一手来源，并标注查询日期。候选内容至少说明：

- 值得去的原因与适合谁；
- 一两句帮助选择的历史或文化背景；
- 所需时间、步行距离、明显爬升或台阶、交通衔接；
- 季节性、拥挤度、预约风险和雨天替代；
- 是否值得为景观、温泉、古建或位置安排特色住宿。

候选池要覆盖不同体验类型，而不是简单罗列网红景点。把候选标成“推荐必选、可选、顺路、建议跳过”，并解释理由。

### 3. 先给判断，再让用户取舍

先给一个最符合当前偏好的推荐方案，再给一到两个真正不同的备选。说明每个方案换来了什么、牺牲了什么，例如“景色更强但多一次换酒店”或“更轻松但少一个远郊景区”。

不要把未经处理的一长串景点重新丢给用户。需要确认时，用小批量、容易回答的问题推进；回答后立即收敛路线。

### 4. 排成体力可持续的路线

- 一天围绕一个核心区域或主题，不以打卡数量作为目标。
- 把长途转场日、重步行日、休息日交替安排；避免连续两天高负荷。
- 对 7–8 公里步行或明显台阶日，下一天默认降载。
- “上山看景再原路下山”不是默认项目；只有景观足够突出且坡度、耗时可接受时才保留，并明确替代方案。
- 频繁换酒店只有在明显减少往返或住宿本身值得体验时才采用。
- 每天写清大致时间段、核心内容、交通、住宿、预计步行/爬升、可删减项与 Plan B。不要制造虚假的分钟级精确度。

### 5. 形成预算

同时给两人合计与人均口径，拆分大交通、市内/包车交通、住宿、餐饮、门票体验和机动金。对尚未预订的价格使用区间和假设，不把估算写成确定价格。至少提供“正常舒适档”；当用户尚无预算概念时，再给节省档和含一晚特色酒店的升级档。

### 6. 交付前复核

检查路线是否存在折返、赶车、连续高负荷、过多换酒店、预约冲突、闭馆日或预算漏项。把已核实事实、估算和个人判断分开表达。若用户选择宽松节奏，优先删项目，不通过压缩吃饭、休息或交通缓冲来塞进行程。

## 参考旧攻略的边界

新行程只选一份结构最匹配的历史攻略作为流程和版式参考，默认只读文字、表格与公式，不遍历全部文件，也不分析图片。只有用户明确要求重新总结长期偏好或比较多份攻略时，才扩大样本；图片仅在会影响内容判断或版式复刻时读取。
